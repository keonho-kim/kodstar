# 이력과 저장소

[기능 명세](../../kodstar-spec.md) · [이력 구현](../architecture/history.md) · [인덱스와 캐시 구현](../architecture/storage.md)

## 명령이 현재 상태를 준비하는 순서

1. 등록 루트, 브랜치, 마지막 체크포인트와 사용할 분석 캐시를 확인한다.
2. 기본 모드는 루트 전체의 파일 metadata를 확인한다. `--verify`는 파일 내용 해시까지 읽는다.
3. 관측한 추적 상태가 달라지면 소스 상태를 보존하고 체크포인트를 공개한다.
4. 마지막 정상 분석이 반영한 체크포인트에서 목표 체크포인트까지의 차이를 적용한다.
5. 분석 작성이 완료된 세대에서 조회를 실행한다. 소스와 환경이 같고 정상 세대가 있으면 해당 세대를 재사용한다.

기본 조회·`status`·`doctor`는 이 흐름을 사용한다. `languages`와 `cache list`는 등록 프로젝트를
선택했을 때 동기화하고 프로젝트가 없으면 전역 보고를 한다. `watch`는 변경 이벤트를 모아 같은 흐름을 실행한다.
이벤트 누락·overflow 또는 재시작은 다음 스캔으로 확인한다. `cache clean`, `cache gc`, 시작 도움말,
stdio 제어 요청은 별도 경로다. `history`와 기본 `history diff`는 소스를 수집한 뒤 이력에서 읽는다.
고정 diff, 브랜치 목록과 브랜치 참조 삭제는 보존 DB에서 처리한다.

기본 metadata 스캔은 파일 단위 변경 확인을 위한 것이다. 같은 크기·시간의 변경까지 확인해야 하면
`--verify`를 선택한다. 삭제는 추적 범위의 순회가 완료된 뒤 확정한다.
자동 체크포인트는 명령과 감시가 관찰한 저장 상태를 나타낸다. 편집기의 저장되지 않은 버퍼와
관찰 사이에 사라진 상태는 수집 범위 밖이다.

### 최신성과 과거 조회

| `freshness` | 읽은 상태 |
|---|---|
| `metadata_checked` | 현재 작업 파일의 metadata를 확인한 분석 |
| `content_verified` | 현재 작업 파일의 내용 해시를 확인한 분석 |
| `not_checked` | 변경 검사를 생략하고 읽은 저장 결과 |
| `checkpoint` | 지정 체크포인트의 보존 입력을 사용한 분석 |

`--no-refresh`는 작업 파일의 변경 확인과 자동 저장·갱신을 생략한다. 고정 과거 조회는 현재 엔진과
설정으로 보존한 입력을 해석하며, 처리 중 현재 브랜치와 작업 파일의 상태는 보존된다.
과거 조회와 `--no-refresh`를 함께 쓰려면 선택한 시점의 호환 분석이 준비돼 있어야 한다.
`history diff --graph`의 `--no-refresh`는 작업 파일 수집만 제어하고, 비교 시점의 분석은 필요에 따라 준비한다.

함수 본문 변경은 해당 사용 사실에 반영한다. export·타입·서명·모듈 경계의 변화는 조회 결과에 의존하는
다른 파일까지 다시 해석한다. 성공·실패 조회 모두 의존성으로 남겨 새 정의와 추가 후보를 반영한다.
변경 영향 집합을 확정하기 어려우면 전체 해석으로 범위를 넓힌다.

## 어디에 무엇이 저장되는가

| 위치 | 데이터와 소유권 |
|---|---|
| `<project>/.kodstar/repository.sqlite` | 원문, 경로·속성, 체크포인트와 부모, 이름·브랜치, 복구 journal |
| `$HOME/.kodstar/config.toml` | 사용자가 작성하는 전역 설정 |
| `$HOME/.kodstar/install.json`, `installation.lock` | 설치 경로·PATH 기록과 설치 수명 lease |
| `$HOME/.kodstar/projects.sqlite`, `registry.lock` | 등록 프로젝트·저장소 identity와 캐시 레지스트리 잠금 |
| `$HOME/.kodstar/<path-hash>/project.json` | 경로 식별·캐시 키 버전·최근 사용 시각 |
| 같은 디렉터리의 `index.sqlite` | 현재 분석 세대와 범위·사실·관계 |
| 같은 디렉터리의 `past.sqlite` | 재사용하는 과거 분석 인덱스 한 개 |
| 같은 디렉터리의 `graph-diff.sqlite` | 최근 체크포인트 쌍의 관계 차이와 근거 |
| 같은 디렉터리의 `lease.lock`, `writer.lock` | 캐시의 사용 수명과 분석 작성 직렬화 |
| `$HOME/.kodstar/gc-state.json` | 자동 캐시 정리 상태 |

SQLite의 WAL·SHM은 해당 DB의 수명을 따른다. 캐시 키에 플랫폼과 canonical 절대 경로의 손실 없는
바이트를 사용하고 저장한 루트를 대조한다. 프로젝트를 옮기면 이력은 프로젝트와 함께 이동하며 새 루트의
분석 캐시를 선택한다. 이전 캐시는 보관 정책의 대상이 된다. 이력 디렉터리는 0700, 새 이력 DB는 0600이다.

분석 캐시는 재생성 가능한 데이터다. 현재 저장 형식은 **19**이며 호환되지 않는 캐시를 열면 오류를 낸다.
같은 프로젝트의 분석 캐시를 명시적으로 다시 만들려면 다음을 실행한다.

```bash
kodstar cache clean --root /work/project
kodstar init /work/project
```

캐시 정리의 현재 기본은 30일 미사용 기준, 전체 2 GiB, 자동 정리 간격 24시간이다.
자동 정리는 명령 실행 시 시간이 지나면 진행하며 현재 사용 중인 캐시는 lease로 보호한다.
크기 초과 시 정리 가능한 오래된 캐시부터 선택한다. 유휴 후보나 접근 권한이 부족하면 보고에 남긴다.
캐시 정리 후 유효한 이력이 있으면 다음 일반 분석 명령이 인덱스를 다시 만들 수 있다.
소스 원문과 체크포인트의 보존 수명은 이력 저장소에서 관리한다.

## 무엇이 체크포인트에 들어가는가

루트 내부의 일반 파일과 symlink에 Git ignore·전역 Git ignore·설정 제외·기본 제외 규칙을 적용한다.
`.git`과 `.kodstar`는 파일과 디렉터리 모두 범위에서 제외한다. 이력은 parser 지원 및 파일 분석 크기
한도와 독립적으로 추적 파일을 보존한다. 큰 파일·바이너리도 저장 대상이다. symlink는 대상 문자열을
저장한다. 복원하는 접근 권한 범위는 Unix 0777이다. 빈 디렉터리, 소유자, ACL, 확장 속성, mtime과
특수 권한은 보존 속성의 범위 밖이다. 제외 설정이 달라져도 과거에 보존한 상태는 기존 체크포인트에 남는다.

기본 브랜치는 `main`이고 체크포인트 ID는 `c`와 양의 정수로 표시한다. 이름은 1~128바이트의
ASCII 영숫자·점·밑줄·하이픈이며 영숫자로 시작한다. 체크포인트 ID 형태는 예약한다.
체크포인트마다 이름 하나를 할당할 수 있다. 같은 이름을 같은 시점에 다시 붙이면 그 상태를 재사용한다.
다른 시점으로 이름을 옮기는 요청은 오류다. 브랜치는 끝 체크포인트의 참조다. 브랜치를 삭제해도 과거
체크포인트와 이름은 보존한다.

### 이력 형식과 복구

현재 이력 형식은 **6**이다. 내용 주소로 동일 바이트를 공유하며 독립 Zstd frame, 깊이 1 델타,
내용 기준 청크를 선택한다. 구체적인 인코딩과 접근 경로는 [이력 구현](../architecture/history.md#원문-저장)에 있다.
일반 명령이 형식 1~5를 만나면 `history upgrade`를 안내한다.
업그레이드는 기존 원문과 참조를 검증하고 ID·이름·브랜치와 복구 journal을 보존한다.
변환·재압축 실패나 취소는 transaction을 되돌린다. 빈 페이지 정리는 변환 커밋 뒤의 별도 단계라
실패한 경우 다시 실행할 수 있다. 알 수 없는 형식과 schema는 진단하며 이력 변환에 필요한 임시 공간은
기존 DB 외에 확보해야 할 수 있다.

## 비교·복원과 실패

파일 diff는 경로별 추가·수정·삭제, 양쪽 해시·종류·권한과 변경 텍스트를 표시한다.
같은 앞뒤 행은 건너뛰고 양쪽 변경 창의 합이 256 KiB·4,096행 이내이면 내부 동일 행까지 대조한다.
그보다 크면 스트리밍 변경 범위를 출력한다. 이 범위는 줄 단위 최소 편집 patch보다 넓을 수 있다.
바이너리와 표시 한도 초과는 `diff_omitted`로 반환한다. 보존과 해시 비교는 앞 단계에서 수행한다.

그래프 diff는 원본 파일, 구문 출처 객체의 논리 키, 관계 종류, 호출·참조식, 조건, type-only 여부로
사용을 맞춘다. 같은 사용의 위치 이동은 관계 변화에서 제외한다. 대상·해석 상태·사용 횟수 변경과
대표 위치를 보고하며 다른 파일이 바뀌어 재해석된 관계도 반영한다. 두 분석의 환경·버전·coverage를
함께 확인한다. 바이트 한도는 비교 작업 전체에, `--limit`은 완료 비교의 출력 행에 적용한다.

복원과 브랜치 전환은 현재 변경을 먼저 내용 검증으로 보존한다. 대상 경로, 추적하지 않은 파일과의
충돌, staging과 대상 파일시스템을 확인한 뒤 실제 파일을 바꾼다. 각 파일의 적용과 완료 여부는
journal에 기록한다. 중단 후 실제 파일과 hash를 대조해 재개하고, 외부 편집을 발견하면 충돌을 보고한다.
복원은 현재 브랜치에 새 소스 상태를 기록한다. 같은 상태면 기존 체크포인트를 재사용한다.

스캔이 완료되지 않거나 파일이 읽는 동안 달라지면 체크포인트 공개를 취소한다. 이력 공개와 분석 공개는
별도의 transaction이다. 이력 성공 후 분석에 실패하면 저장한 체크포인트와 마지막 정상 인덱스를 각각
사용할 수 있다. 기본 조회는 분석 실패를 오류로 보고하며 `status`·`doctor`에서 두 상태의 차이를 확인할 수 있다.
분석 rollback, cache 손상과 취소 상황의 내부 경계는 [인덱스 공개](../architecture/storage.md#공개와-호환성)에 있다.
